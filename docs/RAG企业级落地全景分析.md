# RAG 企业级落地全景分析

> 基于当前项目实现（PGVector + BM25 混合检索 + CrossEncoder 重排序 + 多粒度索引）的系统性梳理，
> 对比个人理解与企业级生产环境之间的差距，明确已覆盖能力与待补充模块。

---

## 一、当前已实现的能力（✅）

| 模块 | 具体实现 | 代码位置 |
|------|---------|---------|
| **向量检索** | PGVector + cosine similarity，显式处理 distance→similarity 转换 | `vector_store.py` |
| **BM25 关键词检索** | `rank-bm25` 基于内存索引 | `vector_store.py` |
| **混合检索（RRF）** | `EnsembleRetriever` 权重融合向量 + BM25 | `vector_store.py` |
| **重排序** | `HuggingFaceCrossEncoder` 精排，GPU/CPU 自适应 | `vector_store.py` |
| **多粒度检索** | 子 chunk 检索 → 父 chunk 上下文（small→large） | `multi_gran_retriever.py` |
| **语义切分** | Embedding 相似度合并相邻 chunk，避免语义切断 | `text_spliter.py` |
| **阈值过滤** | 自定义 `VectorSimilarityThresholdRetriever`，过滤后空结果自动回退 Top-1 | `vector_store.py` |
| **文档解析** | txt/md/html/docx/pptx/pdf（MinerU）多格式支持 | `file_loader.py`, `mineru_loader.py` |
| **增量索引** | `FileTracker` + `TaskQueue` + `BackgroundWorker` 异步扫描与更新 | `vector_store.py` |
| **元数据增强** | 语言/类型/长度等统计信息自动补充 | `metadata_enhancer.py` |

**结论**：检索 pipeline 的工程化程度较高，尤其是**混合检索 + 多粒度 + 重排序**的三层架构，已超越多数基础 RAG 实现。

## 四、工程运维层（生产环境必备）

| 维度 | 当前状态 | 企业级要求 | 优先级 |
|------|---------|-----------|--------|
| **延迟优化** | 串行检索+重排序 | 向量索引选型（HNSW）、重排序 batch 推理、异步并行 | P0 |
| **缓存机制** | 无 | Semantic Cache（相似 query 命中缓存，减少 LLM 调用） | P0 |
| **并发限流** | 无 | 检索/QPS 限流、LLM 生成并发控制、降级策略（关闭重排序） | P0 |
| **A/B 测试** | 无 | 不同检索策略在线对比（BM25 权重、重排序模型、top_n） | P1 |
| **反馈闭环** | 无 | 用户 👍/👎 收集 → 负样本挖掘 → 优化 embedding/重排序模型 | P1 |
| **多租户隔离** | 单 collection | 按用户/项目分 collection，或 metadata 隔离 + 强制过滤 | P1 |
| **安全权限** | 无 ACL | 文档级访问控制，检索时按用户权限预过滤 | P1 |
| **可观测性** | 基础日志 | 结构化日志、各阶段延迟打点（检索/重排/生成/token数） | P0 |

## 五、评估体系（RAG 落地最难的部分）

> **现状**：当前系统完全没有评估框架，无法判断优化是正向还是负向。

### 5.1 三层评估体系

| 层级 | 指标 | 评估方法 |
|------|------|---------|
| **检索评估** | Recall@K、MRR、NDCG | 人工标注 query-doc 相关性对，或自动生成测试集 |
| **生成评估** | 忠实度(Faithfulness)、答案相关性(Answer Relevance)、上下文召回(Context Recall) | RAGAS、ARES、LLM-as-a-Judge |
| **端到端评估** | 用户满意度、问题解决率、首字延迟 | 在线埋点、A/B 测试、人工抽检 |

### 5.2 建议落地顺序

1. **先建检索测试集**：人工标注 50~100 条 `query → 相关 doc_id`，用于验证检索策略改动
2. **引入 RAGAS**：自动化评估 Faithfulness、Answer Relevance、Context Precision
3. **在线埋点**：记录 query、召回数、重排分数、生成 token 数、总延迟
4. **用户反馈收集**：答案下方加 👍/👎，用于后续负样本挖掘

## 八、总结

1. **检索 pipeline 工程化强**：混合检索 + 多粒度 + 重排序三层架构已超越多数基础 RAG 实现
2. **在线链路缺口明显**：Query 改写、路由、去重、上下文压缩、引用校验等关键环节缺失
3. **离线能力基本完备**：文档解析、切分、增量索引已有较好基础，需补充质量监控和版本管理
4. **最大短板是评估**：没有评估体系 = 无法量化优化效果，这是企业落地的首要瓶颈
5. **建议落地顺序**：评估测试集 → Query 改写 → 去重 + Cache → 可观测性 → 反馈闭环
